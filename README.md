# WebBIOS

A web-based BIOS system that loads and boots real `.iso` files using QEMU compiled to WebAssembly.

## What This Is

WebBIOS is a browser-based firmware interface that wraps **QEMU-WASM** (QEMU system emulator compiled to WebAssembly). It can boot real operating systems from ISO images entirely in your browser.

## Project Structure

```
WebBIOS/
├── WebBIOS.html          # BIOS UI shell (this is what you open)
├── out.js                # Emscripten glue for QEMU (generated by build)
├── qemu-system-x86_64.wasm      # QEMU emulator binary (generated by build)
├── qemu-system-x86_64.worker.js # Pthreads worker (generated by build)
├── qemu-system-x86_64.data      # Firmware blobs BIOS/VGA (generated by build)
├── load.js               # File packager preload script (generated by build)
├── build.sh              # One-command build script
├── server.py             # Development server with required security headers
└── README.md             # This file
```

## Prerequisites

- **Linux** or **WSL2** on Windows
- **Docker** installed and running
- **Git**
- **Python 3**
- At least **20 GB free disk space** for the build
- **8 GB RAM** minimum (your machine specs are fine)

## Quick Start

### Step 1: Build QEMU-WASM

Run the build script. This downloads, compiles, and packages everything automatically.

```bash
chmod +x build.sh
./build.sh
```

This will:
1. Clone `ktock/qemu-wasm`
2. Build a Docker image with Emscripten
3. Compile `qemu-system-x86_64` to WebAssembly
4. Package PC-BIOS firmware files
5. Output everything to the `dist/` folder

**Time:** 10-30 minutes depending on your machine and internet.

### Step 2: Copy UI files to dist/

```bash
cp WebBIOS.html dist/
cp server.py dist/
```

### Step 3: Run the server

**IMPORTANT:** You cannot open `WebBIOS.html` directly with `file://`. The browser requires `Cross-Origin-Opener-Policy` and `Cross-Origin-Embedder-Policy` headers for `SharedArrayBuffer`, which QEMU-WASM needs for pthreads.

```bash
cd dist
python3 server.py
```

### Step 4: Open WebBIOS

Go to: http://localhost:8080/WebBIOS.html

1. Watch the POST boot sequence (click to skip)
2. Go to **ISO Library** and drop a bootable `.iso` file
3. Go to **Boot**, select the CD-ROM device
4. Click **Boot Selected Device**
5. The VM display opens and QEMU boots the real ISO

## Where to Get Test ISO Files

### Recommended Small ISOs for Testing

| OS | Size | Download | Notes |
|---|---|---|---|
| **Alpine Linux Standard** | ~180 MB | https://dl-cdn.alpinelinux.org/alpine/v3.19/releases/x86_64/alpine-standard-3.19.1-x86_64.iso | Fastest. Text mode. Ideal first test. |
| **Alpine Linux Extended** | ~250 MB | https://dl-cdn.alpinelinux.org/alpine/v3.19/releases/x86_64/alpine-extended-3.19.1-x86_64.iso | More packages included. |
| **Tiny Core Linux** | ~25 MB | http://www.tinycorelinux.net/15.x/x86_64/release/TinyCore-current.iso | Extremely small. Very fast. |
| **Debian Netinst** | ~400 MB | https://cdimage.debian.org/debian-cd/current/amd64/iso-cd/debian-12.5.0-amd64-netinst.iso | Full installer. Good test. |
| **FreeDOS** | ~20 MB | https://www.freedos.org/download/ | Legacy 16-bit DOS. Boots instantly. |
| **Damn Small Linux** | ~50 MB | Search archive.org for DSL ISO | Classic tiny Linux. |

### My Recommendation for Your First Boot

**Alpine Linux Standard** is the best first test because:
- It is small (~180 MB)
- It boots to a text console quickly
- It does not need much RAM (512 MB works)
- It is a real x86_64 Linux OS

### How to Download

```bash
# Create an ISOs folder
mkdir -p ~/ISOs
cd ~/ISOs

# Download Alpine Linux (recommended first test)
wget https://dl-cdn.alpinelinux.org/alpine/v3.19/releases/x86_64/alpine-standard-3.19.1-x86_64.iso

# Or Tiny Core Linux (smallest)
wget http://www.tinycorelinux.net/15.x/x86_64/release/TinyCore-current.iso
```

Then drag the `.iso` file into the WebBIOS ISO Library dropzone.

## VM Settings for Your Machine (8GB RAM / 6 Cores)

| Guest OS | Recommended RAM | Recommended vCPUs | Expected Performance |
|---|---|---|---|
| Alpine / Tiny Core (text) | 512-1024 MB | 1-2 | Fast |
| Debian/Ubuntu Server | 1024-2048 MB | 2 | Good |
| Lightweight Linux desktop | 2048 MB | 2 | Usable |
| Windows 98/XP | 512 MB | 1 | Slow but functional |
| Windows 10/11 | Not recommended | Not recommended | Very slow on WASM |

**Safety rule:** Never allocate more than 4096 MB guest RAM on an 8GB host.

## How It Works

1. **QEMU-WASM** (by Kohei Tokunaga / NTT) is QEMU compiled to WebAssembly with a custom TCG backend that translates QEMU IR to WASM instructions.
2. **Multi-threaded TCG** uses Web Workers + `SharedArrayBuffer` to JIT-compile hot translation blocks.
3. **WebBIOS** is the UI shell that:
   - Reads ISO files via the File API
   - Constructs QEMU command lines
   - Bridges the VGA framebuffer to a `<canvas>`
   - Bridges keyboard/mouse input to emulated devices

## Troubleshooting

### "SharedArrayBuffer is not available"

You opened the file directly (`file://`). You must use `server.py` which sends the required COOP/COEP headers.

### "QEMU module failed to load"

Make sure all 5 files from the build are in the same directory as `WebBIOS.html`:
- `out.js`
- `qemu-system-x86_64.wasm`
- `qemu-system-x86_64.worker.js`
- `qemu-system-x86_64.data`
- `load.js`

### Build fails in Docker

Make sure Docker has at least 8GB RAM allocated in Docker Desktop settings. QEMU compilation is memory-intensive.

### Browser crashes during boot

Reduce guest RAM in VM Settings. Start with 512 MB for text-mode Linux.
